## Asking Whether It Fits

A top mark must be one of the marks, and the printed number is not in the list. Line 2 starts `top` at a value that no mark can beat, so line 5 never runs.

You did not need to calculate anything to see this. A plain question, "could this answer be true?", catches many bugs.

**Ask whether an answer could be true before you trust it.**

## Say When a Tool Wrote Your Code

If a model wrote code that you hand in, say so. Your teacher is judging what you can do, so your teacher needs to know which part is yours. The runner cannot tell who wrote a program, and often a teacher cannot either.

Saying so also reminds you of the other half of the job. Whoever hands in a program is responsible for checking that it works.

**If you hand it in, say who wrote it, and check that it works.**

## Three Jobs, Kept Apart

A model predicts text one token at a time. Its code is often good because of the code it has seen, practice against tests, and the run-and-fix loop. A computer runs that text exactly and reports what happened.

Neither of them knows what you wanted, so that last part stays with you.

**The model writes, the computer runs, and you check.**

You now know how a model writes, and how its work gets checked. Can you explain it to a friend, in cases you have not seen?
