## Another View: the Picture Map

Here is a different view of 40 pictures, and it has nothing to do with the encoder. A different program sorted these pictures by what they show. It gave each picture a list of 512 numbers, and we flattened those to two for the screen, as we did for the word map.

**These dots are not latent codes.**

<!-- STEP id="s2" -->
## Tap the Map

Tap anywhere on this picture map. The screen finds the nearest dot and shows that stored picture, even if you tap far from every dot. Nothing new is made here, because this map has no decoder behind it. Its use is to show that a program can sort pictures by what they show.

**The picture map sorts stored pictures. It cannot make a new one.**

<!-- STEP id="s3" -->
## The Problem That Is Left

To make a new picture, you need a new latent code that the decoder can open. A random latent code gives only speckle, and a map of stored pictures gives only what already exists.

**So how could anything get from random numbers to a good latent code?**
